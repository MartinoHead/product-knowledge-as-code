# template-project - Development Workflow

## Quick Start: Feature Implementation (PKAC Pattern)

### Step 1: Create Knowledge Files
```bash
# Create feature directory if it doesn't exist
mkdir -p knowledge/feature-name

# Create three synchronized knowledge files:
# 1. Markdown specification (README-style)
touch knowledge/feature-name/feature-name.md

# 2. YAML rules (structured)
touch knowledge/feature-name/feature-name.yaml

# 3. Gherkin scenarios (BDD)
touch knowledge/feature-name/feature-name.feature
```

### Step 2: Verify Sync
```bash
npm run verify:sync
# Output: "Knowledge sync OK (X feature(s), md/yaml/gherkin aligned)"
```

### Step 3: Generate Tests
```bash
npm run generate:tests
# Output: "Generated tests/api/feature-name.api.spec.ts"
#         "Generated tests/playwright/feature-name.spec.ts"
```

### Step 4: Implement Code
Update:
- `src/routes/feature.ts` - Route handlers
- `src/services/feature-service.ts` - Business logic
- `src/repositories/feature-repository.ts` - Data access
- `src/data/feature-store.ts` - In-memory fallback (optional)
- `src/middleware/*.ts` - Shared middleware (auth, validation, etc.)

### Step 5: Implement Tests
Complete TODO placeholders in generated test files:
- `tests/api/feature-name.api.spec.ts` - API tests
- `tests/playwright/feature-name.spec.ts` - UI/integration tests

Maintain rule ID references in test names: `test('[RULEID-001] ...')`

### Step 6: Verify Everything
```bash
npm run lint              # Lint check
npm run typecheck         # Type safety
npm run verify:sync       # Knowledge still synchronized
npm run test:api          # API tests pass
npm run test:ui           # UI tests pass
npm run test              # All tests pass
```

## Knowledge File Templates

### Template: markdown (`feature-name.md`)

```markdown
# Feature Name

## Intent
Brief explanation of the feature's purpose and who uses it.

## Happy Path
- User does X
- System does Y
- Result is Z

## Expected Behavior
- Behavior point 1
- Behavior point 2
- Error handling approach

## Rules
- RULE-001: Title of rule
- RULE-002: Title of rule

## Edge Cases
- Edge case 1: description
- Edge case 2: description

## Non-Goals
- Things deliberately out of scope

## API Contract (if applicable)

**Endpoint:** `METHOD /v1/resource`

**Request:**
```json
{
  "field": "value"
}
```

**Success Response (200 OK):**
```json
{
  "result": "success"
}
```

**Error Response (400 Bad Request):**
```json
{
  "error": "error_code",
  "message": "description"
}
```
```

### Template: YAML (`feature-name.yaml`)

```yaml
feature: Feature Name
intent: Brief description of purpose
rules:
  - id: RULE-001
    title: Rule title
    description: Detailed description
    acceptance_criteria:
      - Criterion 1
      - Criterion 2
  - id: RULE-002
    title: Another rule
    acceptance_criteria:
      - Criterion 1
```

### Template: Gherkin (`feature-name.feature`)

```gherkin
Feature: Feature Name
  Description of what this feature does

  @RULE-001
  Scenario: Rule 001 scenario
    Given some precondition
    When action is taken
    Then expected result happens

  @RULE-002
  Scenario: Rule 002 scenario
    Given another precondition
    When another action
    Then another result
```

# 2. Verify and generate

# 3. Implement endpoint
# Edit: src/routes/users.ts
# Edit: src/services/user-service.ts
# Edit: src/repositories/user-repository.ts

# 4. Complete tests
# Fill TODOs in: tests/api/users.api.spec.ts
# Fill TODOs in: tests/playwright/users.spec.ts

# 5. Verify everything
npm run lint
npm run typecheck
npm run verify:sync
npm run test
```

### Example 2: Fix Production Bug

```bash
# 1. Update knowledge with incident details
# Edit: knowledge/existing-feature/existing-feature.md (add edge case)
# Edit: knowledge/existing-feature/existing-feature.yaml (add rule for bug)
# Edit: knowledge/existing-feature/existing-feature.feature (add scenario)

# 2. Regenerate and update tests
npm run verify:sync
npm run generate:tests
# Update test implementations with bug prevention checks

# 3. Fix code
# Edit: src/services/feature-service.ts
# Edit: src/routes/feature.ts

# 4. Verify fix
npm run lint
npm run typecheck
npm run test
```

### Example 3: Refactor without Feature Changes

```bash
# If refactoring code WITHOUT changing behavior:
# 1. Keep knowledge files unchanged
# 2. Do NOT regenerate tests (tests unchanged)
# 3. Just refactor code
# 4. Run tests to ensure they still pass

# If refactoring REVEALS a behavior change:
# 1. Update knowledge files first
# 2. Verify sync
# 3. Regenerate tests
# 4. Complete test implementations
# 5. Deploy updated code and tests
```

## Rule IDs Naming Convention

Format: `[FEATUREPREFIX]-###`

Examples:
- Registration: `REG-001`, `REG-002`, `REG-003`
- Login: `LGN-001`, `LGN-002`, `LGN-003`
- Create User: `USR-001`, `USR-002`, `USR-003`
- Get User: `USG-001`, `USG-002`, `USG-003`
- List Users: `LISTUSR-001`, `LISTUSR-002`, `LISTUSR-003`
- Checkout: `CHK-001`, `CHK-002`, `CHK-003`

**Important:** Rule IDs must appear in:
- ✅ `feature-name.yaml` as `id: RULE-###`
- ✅ `feature-name.feature` as `@RULE-###` tags
- ✅ Test names: `test('[RULE-###] ...')`

This creates traceability: Knowledge → Rule ID → Test → Implementation

```

## CI/CD Pipeline (GitHub Actions)

When you push to main branch:

1. ✅ Quality gates: lint, typecheck, knowledge sync
2. ✅ Test generation: verify sync before running tests
3. ✅ API tests: npm run test:api
4. ✅ Build: Docker build
5. ✅ Deploy: Cloud Run deployment
6. ✅ Smoke tests: Health check, auth flow, endpoints
7. ✅ Auto-rollback: If smoke tests fail

**Never merge to main if:**
- `npm run verify:sync` fails
- `npm run test:api` fails
- Knowledge and tests are out of sync
